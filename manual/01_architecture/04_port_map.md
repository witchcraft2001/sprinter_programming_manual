## Обзор системы декодирования портов

В Sprinter декодирование внешних портов I/O реализовано через **DCP**
(Dynamic Configuration Port). Важно разделять три разных числа:

1. **реальный порт Z80** — адрес, который программа кладёт в `C`/`BC` и
   использует в `IN`/`OUT`;
2. **ячейка карты DCP** — адрес внутри страницы карты портов (`DCP_PAGE=#40`),
   вычисляемый из части битов реального порта, направления `RD/WR`, DOS-флага и
   выбранной конфигурации;
3. **внутренний код DCPP** — байт вроде `#88`, `#C1`, `#E8`, по которому ACEX
   уже выбирает конкретный регистр.

Файл `DCP.MIF` описывает начальное содержимое аппаратной RAM/LUT в ACEX, но для
прикладной программы это **не список публичных портов**. Штатную карту при
загрузке строит BIOS из `sprinter_bios/src/bios/exp/DCP.ASM`, а ZX-режим и
конфигурации совместимости могут переписывать её динамически.

При каждой операции I/O:
1. выбранные биты адреса порта (`A0..A2`, `A5..A7`, `A13..A15`), направление
   чтение/запись и флаги режима выбирают ячейку карты DCP;
2. карта возвращает внутренний код `DCPP`;
3. логика ACEX/MAX7000 обслуживает устройство, соответствующее этому коду;
4. для некоторых устройств старшие биты реального адреса (`A15..A8`) остаются
   важны уже после выбора DCPP, например IDE, ISA и Kempston Mouse.

### Типы портов (`TYPE[3..0]`)

| TYPE | Код | Описание |
|------|-----|----------|
| 0 | `0000` | Нет функции (заглушка) |
| 1 | `0001` | HDD данные (INIR/OTIR через Z80) |
| 2 | `0010` | Запись в порт (системный) |
| 3 | `0011` | Чтение AY / COVOX-read |
| 4 | `0100` | Чтение клавиатуры |
| 5 | `0101` | Kempston Mouse |
| 6 | `0110` | Чтение/запись видео (RGMOD/RGADR) |
| 7 | `0111` | MAX7000: FDD/HDD/CMOS |
| C | `1100` | Системные порты (страницы, режимы) |

## Полная карта портов

### Управление памятью (банкинг)

| Порт | Имя | Чтение / Запись | Описание |
|------|-----|-----------------|----------|
| `#82` | `EmmWin.P0` | RW | Номер страницы в окне 0 (`0x0000–0x3FFF`) |
| `#A2` | `EmmWin.P1` | RW | Номер страницы в окне 1 (`0x4000–0x7FFF`) |
| `#C2` | `EmmWin.P2` | RW | Номер страницы в окне 2 (`0x8000–0xBFFF`) |
| `#E2` | `EmmWin.P3` | RW | Номер страницы в окне 3 (`0xC000–0xFFFF`) |

В старой статической `DCP.MIF` есть дополнительные алиасы для внутренних
регистров страниц, но для прикладного кода используйте публичные адреса
`#82/#A2/#C2/#E2`: именно они определены как `SLOT0..SLOT3` в BIOS/DSS.

```asm
EmmWin.P0   EQU     #82
EmmWin.P1   EQU     #A2
EmmWin.P2   EQU     #C2
EmmWin.P3   EQU     #E2

; Переключить окно 1 на страницу 7 (RAM)
        ld      a, 7
        out     (EmmWin.P1), a
```

### Видео и графика

| Порт | Имя | Чтение / Запись | Описание |
|------|-----|-----------------|----------|
| `#89` | `PORT_Y` / `RGADR` | W | Запись адреса палитры / номера цвета |
| `#C9` | `RGMOD` | W | Режим видео и управление экраном |
| `#FE` | `BORDER` | W | Бордюр ZX (биты [2:0] = цвет), внутренний DCPP `#C2` |
| `#204E` | `ALL_MODE` | W | Графический режим (bit[1:0]: 00=ZX, 01=320×256, 10=640×256), внутренний DCPP `#C3` |

**Порт `#89` (PORT_Y / RGADR)** — адрес/данные палитры:

Запись числа от 0 до 255 выбирает индекс палитры. Следующая запись задаёт цвет в формате BGR (6-6-6).

**Порт `#C9` (RGMOD)**:

| Бит | Назначение |
|-----|-----------|
| 0 | Double buffer flip: 0 = экран A активен, 1 = экран B активен |
| 1 | Screen off: 1 = экран выключен, 0 = включён |
| [7:2] | Не используются |

```asm
RGADR           EQU     #89
RGMOD           EQU     #C9

; Установить палитровую запись 0 в белый (R=63, G=63, B=63)
        ld      a, 0            ; индекс цвета
        out     (RGADR), a
        ld      a, 63           ; R
        out     (RGADR), a
        ld      a, 63           ; G
        out     (RGADR), a
        ld      a, 63           ; B
        out     (RGADR), a

; Переключить отображаемый буфер (double buffering)
        in      a, (RGMOD)
        xor     1
        out     (RGMOD), a
```

**Порт `#204E` (ALL_MODE)** — выбор графического режима:

| Значение | Режим |
|---------|-------|
| `#00` | ZX Spectrum (256×192, атрибуты) |
| `#01` | 320×256, 8bpp (256 цветов из палитры) |
| `#02` | 640×256, 4bpp (16 цветов из палитры) |
| `#80` | Pentagon 128 совместимость |

```asm
ALL_MODE        EQU     #204E

; Включить режим 320×256
        ld      a, #01
        ld      bc, ALL_MODE
        out     (c), a
```

### COVOX (PCM DAC)

| Порт | Имя | Описание |
|------|-----|----------|
| `#FB` / `#4F` | `CBL_WR` / `COVOX_OUT` | Запись 8-битного аудиосэмпла; внутренний DCPP `#88` |
| `#004E` | `CBL_XX` / `CBL_DIR` | Управление режимом COVOX-Blaster; внутренний DCPP `#89` |

**Порт `#004E` (режим COVOX/CBL)**:

| Бит | Назначение |
|-----|-----------|
| 7 | 1 = COVOX включён |
| 6 | 1 = стерео режим (16-битный) |
| 5 | 1 = 16-битные сэмплы |
| 4 | 1 = прерывания от COVOX |
| [3:0] | Частота дискретизации |

Таблица частот (биты [3:0]):

| Код | Частота |
|-----|---------|
| `#0` | 15 625 Гц (старый совместимый режим) |
| `#1` | 21 875 Гц (старый совместимый режим) |
| `#2`–`#7` | зарезервировано |
| `#8` | 7 812.5 Гц |
| `#9` | 10 937.5 Гц |
| `#A` | 15 625 Гц |
| `#B` | 21 875 Гц |
| `#C` | 31 250 Гц |
| `#D` | 43 750 Гц |
| `#E` | 54 687.5 Гц |
| `#F` | 109 375 Гц |

```asm
COVOX_DAT       EQU     #FB
COVOX_MOD       EQU     #004E

; Настроить COVOX: моно, 8-bit, 31.25 кГц (код #C)
        ld      a, #8C          ; bit7=on, bits[3:0]=#C
        ld      bc, COVOX_MOD
        out     (c), a

; Вывести сэмпл
        ld      a, (sample_ptr)
        out     (COVOX_DAT), a
```

### AY-3-8910 (звуковой синтезатор)

AY эмулируется внутри FPGA ACEX 1K30.

| Порт | Имя | Описание |
|------|-----|----------|
| `#FFFD` | `AY_A_WR` | Запись номера регистра AY (0–15) — стандарт ZX-128 |
| `#BFFD` | `AY_D_WR` | Запись данных в текущий регистр AY — стандарт ZX-128 |
| `#FFFD` | `AY_D_RD` | Чтение данных из текущего регистра AY |

> **Важно:** `#90`/`#91` и `#52` — это внутренние DCPP-коды ACEX, а не
> переносимые публичные I/O-адреса для прикладной программы. В ZX-совместимой
> карте реальные порты `#FFFD`/`#BFFD` перенаправляются в DCP на внутренние
> `#90`/`#91`, а чтение `#FFFD` — на внутренний код чтения AY.
>
> Порты `#8D`/`#8E` встречаются **только в комментариях `DCP.MIF`** и ни одной
> строкой логики FPGA как AY не дешифрируются — это устаревшая аннотация,
> использовать их нельзя.

```asm
AY_REG          EQU     #FFFD   ; выбор регистра / чтение данных
AY_DAT_WR       EQU     #BFFD   ; запись данных

; Записать значение в регистр AY: REG → VALUE
; Пример: установить громкость канала A (регистр 8) = 15
        ld      a, 8
        ld      bc, AY_REG
        out     (c), a
        ld      a, 15
        ld      bc, AY_DAT_WR
        out     (c), a

; Прочитать текущее значение
        ld      bc, AY_REG
        in      a, (c)
```

### Flash / ROM

| Порт | Имя | Описание |
|------|-----|----------|
| `#5C` | `ROM_RG` / `ROM.SLOT0` | Управление Flash/FastRAM в системном режиме; внутренний DCPP `#8F` |

```asm
ROM_RG          EQU     #5C

; Включить запись во Flash (бит 4)
        ld      a, #10
        out     (ROM_RG), a

; Выключить запись
        xor     a
        out     (ROM_RG), a
```

### Клавиатура ZX и Kempston

| Порт | Имя | Описание |
|------|-----|----------|
| `#FE` | ZX_KBD | Чтение клавиш ZX (A8–A12 = строка клавиатуры) |
| `#40` | KBD_READ | Чтение расширенной клавиатуры (DCP type 4) |
| `#F8` | `P_KBD_OUT` | Запись команды в контроллер PS/2 |
| `#FE` | `P_KBD_IN` | Чтение ответа от PS/2 контроллера |

Порт `#FE` — стандартный ZX-порт: биты [4:0] = состояние 5 клавиш строки, бит 6 = tape in, бит 7 = tape out.

### PS/2 клавиатура (через SIO Z84C15)

Основной способ приёма PS/2 сканкодов — через встроенный **SIO канал A** процессора Z84C15:

| Порт | Имя | Описание |
|------|-----|----------|
| `#18` | `SIO_DATA_REG_A` | Принятый байт от PS/2 клавиатуры |
| `#19` | `SIO_CONTROL_A` | Статус SIO; бит 0 = 1 когда байт готов |
| `#1A` | `DAT_B` | SIO канал B данные (KBD_DAT) |
| `#1B` | `COM_B` | SIO канал B управление (KBD_COM) |

### Kempston Mouse

| Порт | Описание |
|------|----------|
| `#FADF` | Кнопки мыши (биты [2:0]); внутренний DCPP `#58` |
| `#FBDF` | X-координата мыши |
| `#FFDF` | Y-координата мыши (инверсная) |

В старой статической `DCP.MIF` можно встретить запись `58 : 5000`; это
внутренняя DCP-классификация. В штатной BIOS-карте прикладной код обычно
использует полные 16-битные адреса выше.

```asm
MOUSE_BTN       EQU     #FADF

; Прочитать кнопки мыши
        ld      bc, MOUSE_BTN
        in      a, (c)
        and     #07             ; 3 кнопки
```

|------|-----|----------|
| `#10` | `CTC_CH0` | Канал 0 |
| `#11` | `CTC_CH1` | Канал 1 |
| `#12` | `CTC_CH2` | Канал 2 (системный таймер ~50 Гц) |

### FDD (дисковод) — через MAX7000

| Порт | Назначение |
|------|-----------|
| `#1F`/`#0F` | WG93 статус (RD) |
| `#3F` | WG93 трек |
| `#5F` | WG93 сектор |
| `#7F` | WG93 данные |
| `#FF` | WG93 команда (WR_PDOS) |
| Бит ISA_A20 | А20 управление (порт `#1B`) |

Доступ через MAX7000 с паттерном `TYPE=7` в DCP.MIF. FDD контроллер совместим с WD1793.

### IDE (жёсткий диск)

IDE порты декодируются через внешнюю шину — адрес на старших битах A15–A8 + порт.

**Запись (WR):**

| Порт | Имя | ATA-эквивалент |
|------|-----|----------------|
| `#0150` | `HDW_DAT` | 1F0h Data |
| `#0151` | `HDW_ERR` | 1F1h Features/Error |
| `#0152` | `HDW_CNT` | 1F2h Sector Count |
| `#0153` | `HDW_SEC` | 1F3h Sector Number |
| `#0154` | `HDW_CLL` | 1F4h Cylinder Low |
| `#0155` | `HDW_CLH` | 1F5h Cylinder High |
| `#4152` | `HDW_DRV` | 1F6h Drive/Head |
| `#4153` | `HDW_COM` | 1F7h Command |
| `#4154` | `P_HD3F6` | 3F6h Device Control |

**Чтение (RD):**

| Порт | Имя | ATA-эквивалент |
|------|-----|----------------|
| `#0050` | `HDR_DAT` | 1F0h Data |
| `#0051` | `HDR_ERR` | 1F1h Error |
| `#0052` | `HDR_CNT` | 1F2h Sector Count |
| `#0053` | `HDR_SEC` | 1F3h Sector Number |
| `#0054` | `HDR_CLL` | 1F4h Cylinder Low |
| `#0055` | `HDR_CLH` | 1F5h Cylinder High |
| `#4052` | `HDR_DRV` | 1F6h Drive/Head |
| `#4053` | `HDR_CTL` | 1F7h Status |
| `#4055` | `P_HD3F7` | 3F7h Alt Status |

Биты статуса (`HDR_CTL`):

| Бит | Имя | Описание |
|-----|-----|----------|
| 7 | BSY | Устройство занято |
| 6 | RDY | Устройство готово |
| 3 | DRQ | Данные готовы к передаче |
| 0 | ERR | Ошибка |

Данные передаются через `HDW_DAT`/`HDR_DAT` с командами `OTIR`/`INIR` (блочный режим).

|----------|---------|
| `#1C` | CMOS_DAT_RD |

### ISA слот

| Значение | Описание |
|----------|----------|
| `#9FBD` | `Port.ISA` — базовый порт ISA |
| `#C000` | `Port.IsaAdrBase` — базовый адрес ISA в пространстве памяти |

ISA адрес формируется через регистр `ISA_PORT[7..0]`, биты A[9:2] из регистра ISA_PORT.

```asm
Port.ISA        EQU     #9FBD
Port.IsaAdrBase EQU     #C000

; Вывести байт на ISA порт (например, COM1: #3F8)
        ld      bc, Port.ISA
        ld      a, #F8          ; младший байт ISA-адреса
        out     (c), a
```

> **Замечание:** В исходниках `espprobe/sp_equ.asm` и SDK эти константы исторически определены как `Port.ISA` и `isa_adr_base` (в разных стилях). В этом руководстве используется единый стиль `Port.*` для читаемости; при работе с существующим кодом используйте имена из его `sp_equ.asm`.

прикладная программа. Внутренний DCPP-код указан отдельно: это то, что лежит в
карте DCP после декодирования, а не адрес для `IN`/`OUT`.

| Реальный порт / шаблон | Доступ | Группа | Внутренний DCPP | Назначение |
|------------------------|--------|--------|-----------------|------------|
| `#10`–`#13` | RW | Z84C15 CTC | не DCP | Счётчики/таймеры Z84C15 |
| `#18`–`#1B` | RW | Z84C15 SIO | не DCP | SIO A/B, в т.ч. PS/2-клавиатура |
| `#82`, `#A2`, `#C2`, `#E2` | RW | ACEX banking | `#E8`, `#E9`, `#EA`, `#F0` | Окна памяти 0..3 |
| `#FE` | R | ZX keyboard | `#40` | Матрица ZX-клавиатуры, tape/sync bits |
| `#FE` | W | ZX border/beeper | `#C2` | Бордюр, beeper/tape out |
| `#89` | W | Video | `#C4` | `PORT_Y` / `RGADR` |
| `#C9` | W | Video | `#C5` | `RGMOD`, double buffer/screen |
| `#204E` | W | Video | `#C3` | `ALL_MODE`, ZX/320/640 режимы |
| `#FB`, `#4F` | W | COVOX/CBL | `#88` | Вывод PCM-сэмплов |
| `#004E` | RW | COVOX/CBL | `#89` | Регистр режима COVOX-Blaster |
| `#FFFD` | W/R | AY | `#90` / `#52` | Выбор регистра AY / чтение данных |
| `#BFFD` | W | AY | `#91` | Запись данных AY |
| `#7FFD` | W | ZX 128 | `#C1` | Pentagon/ZX128 paging |
| `#1FFD` | W | Scorpion | `#C0` | Scorpion ZS-256 paging |
| `#FADF`, `#FBDF`, `#FFDF` | R | Kempston Mouse | `#58` | Кнопки, X, Y |
| `#1F`, `#3F`, `#5F`, `#7F`, `#FF` | RW | FDD WG93 | `#10`–`#15` | WD1793/WG93, TR-DOS/FDD |
| `#0050`–`#0055`, `#4052`–`#4055` | R | IDE | `#20`–`#29` | ATA-регистры чтения |
| `#0150`–`#0155`, `#4152`–`#4154` | W | IDE | `#20`–`#28` | ATA-регистры записи |
| `#FFBD`, `#DFBD`, `#BFBD` | RW/W/W | CMOS/RTC | `#1C`, `#1D`, `#1E` | Данные/адрес CMOS |
| `#9FBD` | RW | ISA | `#1B`/`#32` | ISA control/port gateway |
| `#3C`, `#7C`, `#24`, `#74` | W | System/CNF | `#C6` | Системный режим, выбор карты DCP/CNF |
| `#5C` | W | ROM/FastRAM | `#8F` | Управление ROM/FastRAM в системном режиме |

Главный практический вывод: `#40`, `#52`, `#58`, `#88`, `#90`, `#91`,
`#C0`–`#C5`, `#E8`–`#F0` в исходниках ACEX/BIOS часто означают **внутренний
DCPP-код**. Если такой номер попал в документацию как "порт", его нужно
сверять с BIOS-картой DCP. Например, пользовательская программа пишет в AY по
`#FFFD/#BFFD`, а не по `#90/#91`; в COVOX — по `#FB/#4F` и `#004E`, а не по
`#88/#89`; бордюр — через `OUT (#FE),A`, а не через `#C2`.

### Как адрес CPU попадает в DCP

В штатной карте портов DCP не использует все 16 бит адреса. Адрес ячейки карты
строится из выбранных линий:

```
DCP_ADDR =
    (CNF[4:3] << 12) | (PN5 << 11) | (DOS << 10) | (READ << 9) |
    (A15..A14 << 7) | (A13 << 4) | (A7 << 3) | (A6..A5 << 5) |
    (A2..A0)
```

Биты `A3`, `A4` и `A8..A12` не участвуют в выборе ячейки, поэтому многие
порты имеют естественные алиасы. Например, `#204E` для `ALL_MODE` выбран как
удобный публичный адрес; по маске карты ему соответствуют и другие адреса с
теми же значимыми битами.

### Как менять адресацию через DCP

Правильный путь — менять **карту DCP**, а не пытаться писать во внутренние
коды ACEX как в порты. BIOS держит карту в странице `DCP_PAGE = #40` и
инициализирует её таблицей записей из `sprinter_bios/src/bios/exp/DCP.ASM`.
Запись вида:

```asm
        DW      base_selector
        DW      selector_mask
        DB      ACEX.Some_Internal_Code
```

означает: все ячейки карты, для которых `(addr & selector_mask) ==
(base_selector & selector_mask)`, получают указанный внутренний DCPP-код.
Этим способом один реальный порт можно открыть только на чтение, только на
запись, только в DOS/не-DOS, только в выбранной CNF-карте, либо сделать
набор алиасов.

Для кода BIOS/расширений есть функция `BIOS.DCP_CONFIG = #F4`:

```asm
; HL = base_selector, DE = selector_mask, B = внутренний DCPP-код ACEX
; A/C = BIOS.DCP_CONFIG (#F4)
        ld      hl, base_selector
        ld      de, selector_mask
        ld      b, ACEX.Some_Internal_Code
        ld      a, #F4
        ld      c, #F4
        rst     #08
```

Для обычных приложений это низкоуровневый механизм: сохраняйте старую карту,
работайте под `DI`, не занимайте внутренние порты Z84C15, и возвращайте карту
при выходе. Если нужно только поменять содержимое виртуального регистра/ячейки
в уже настроенной карте, BIOS использует `BIOS.SET_PORTS = #F8`: именно так
меняются значения виртуальных ROM/RAM-регистров, но сама адресная маска порта
задаётся через `DCP_CONFIG` или таблицу `DCP.ASM`.

Пакет `ZX` делает это на уровне
готовых профилей. В `.ZX` файлах ключи `/7FFD`, `/1FFD`, `/sprinter`,
`/ret-zx`, `/ret-fn` выбирают совместимую конфигурацию; BIOS/ZX-меню затем
настраивают DCP так, чтобы реальные ZX-порты попадали на нужные внутренние
коды: `#7FFD → ACEX.Pent_7FFD (#C1)`, `#1FFD → ACEX.Scorp_1FFD (#C0)`,
`#FFFD/#BFFD → AY (#90/#91)`, `#FE → keyboard/border (#40/#C2)`. Поэтому
Pentagon/Scorpion-совместимость достигается не изменением программ, а
перепривязкой DCP-карты под ожидаемую адресацию портов.

## Ключевые моменты

> - В прикладном коде используйте реальные I/O-адреса, а не внутренние DCPP-коды из ACEX/`DCP.MIF`.
> - BIOS строит карту DCP в странице `#40`; `DCP.MIF` — не публичная карта портов для программ.
> - Память переключается через `#82`/`#A2`/`#C2`/`#E2` (EmmWin.P0–P3).
> - Видео: `#89` (палитра/PORT_Y), `#C9` (RGMOD), `#204E` (ALL_MODE), `#FE` (бордюр).
> - IDE использует нестандартные Z80-порты с старшими битами адреса.
> - AY: реальные порты `#FFFD`/`#BFFD`; внутренние `#90`/`#91`/`#52` — DCPP-коды, не публичные адреса.
> - COVOX/CBL: реальные порты `#FB`/`#4F` для данных и `#004E` для режима; внутренние `#88`/`#89` — DCPP-коды.
> - Порты `#8D`/`#8E` — устаревшая аннотация `DCP.MIF`, использовать их нельзя.
