# 5.5 Палитра и порт #89

## Где живёт палитра

Палитра — это **не отдельная RAM в FPGA**, а часть VRAM-страницы `#50`. Та же страница, в которой лежат пиксели первого экрана, в конце каждой 1024-байтной строки содержит регистры палитры:

```
VRAM страница #50: 256 строк × 1024 байт
┌─────────────────┬─────────────────┬────────────────┬─────────────┐
│ пиксели экрана A│ пиксели экрана B│ дескрипторы    │ палитра     │
│   [0 .. 319]    │  [320 .. 639]   │  [640 .. 991]  │ [992..1023] │
└─────────────────┴─────────────────┴────────────────┴─────────────┘
                                                       ↑
                                              offset $3E0..$3FF
```

* `PORT_Y` (порт `#89`) выбирает **индекс цвета** 0..255 (он же номер строки VRAM).
* На каждой строке байты по смещению `$3E0..$3FF` декодируются FPGA в палитровые регистры.
* CPU-окно роли не играет — декодируются только младшие 10 бит адреса. То есть `WIN0+$03E0`, `WIN1+$43E0`, `WIN2+$83E0`, `WIN3+$C3E0` — это **один и тот же** палитровый регистр.

Подтверждено эмулятором MAME (`mame/src/mame/sinclair/sprinter.cpp:1240-1308`) и проверено на железе (`examples/30_paltest` в SDK).

## Восемь страниц палитры

Внутри блока `$3E0..$3FF` — 8 палитровых страниц по 4 байта каждая:

| Страница | Смещение | WIN3-адрес | Назначение                       |
|----------|----------|-----------|----------------------------------|
| 0        | `$3E0`   | `#C3E0`   | палитра экрана-буфера 0           |
| 1        | `$3E4`   | `#C3E4`   | палитра экрана-буфера 1           |
| 2        | `$3E8`   | `#C3E8`   |                                  |
| ...      | ...      | ...       |                                  |
| 7        | `$3FC`   | `#C3FC`   |                                  |

> **Палитра и двойная буферизация.** Отображаемая палитра-страница следует за
> отображаемым видеобуфером (см. [5.7](07_double_buffer.md)): пока виден буфер 0 — активна
> палитра 0 (`#C3E0`), при flip на буфер 1 — палитра 1 (`#C3E4`). Чтобы цвета не «мигали»
> при переключении буферов, записывайте **одинаковую палитру в обе страницы** (`#C3E0` и
> `#C3E4`). Разные палитры на буферах — штатный приём для покадровых эффектов.

В пределах одной страницы 4 байта:

| Смещение | Содержимое  | Диапазон |
|----------|-------------|----------|
| `+0`     | **R**       | 0..255 |
| `+1`     | **G**       | 0..255 |
| `+2`     | **B**       | 0..255 |
| `+3`     | Y / unused  | —        |

## Порт `#89` — особенности

```asm
PORT_Y          EQU #89     ; псевдонимы: RGADR
```

* **`OUT (#89), A`** — пишет индекс строки VRAM = индекс цвета палитры.
* **`IN A, (#89)`** — **не возвращает текущий `PORT_Y`**, а читает регистр CBL (COVOX-Blaster). Это write-only порт по линии Y.

Если нужен счётчик в коде — держи его в обычном регистре (`E`, `B'`, переменной), а не пытайся читать через `IN`. Идиома `in a,(#89): inc a: out (#89),a` из ранних SDK работает «по совпадению» из-за того, что `A` всё равно перетирается через OUT, но `INC A` действует на мусор из CBL и индекс «прыгает».

После работы с палитрой/VRAM обязательно загнать `PORT_Y` в безопасную зону `$C0..$FF`, как и при обычной работе с VRAM (см. [5.1 Обзор видео](01_video_overview.md), правило №1):

```asm
        ld      a, #C0
        out     (#PORT_Y), a
```

## Способ 1: одна запись через BIOS `#A4` (медленно, но просто)

Реальный ABI обработчика `PIC_SET_PAL` (см. `FUNC_SCREEN.ASM`: **`HL` — указатель на данные, `E` — начальный цвет, `D` —
число цветов, `A` — страница палитры, `B` — PAL-mask**. Данные идут по 4 байта на цвет
в порядке **`B, G, R, Y`** (значения 8-битные, `0..255`).

```asm
Bios.SetPalette EQU #A4

; Установить цвет 10 = ярко-оранжевый (R=255, G=128, B=0)
color10:  db 0, 128, 255, 0         ; порядок байт: B, G, R, Y (0..255)

        ld      hl, color10         ; HL = указатель на данные цвета
        ld      e, 10               ; начальный индекс цвета (0..255)
        ld      d, 1                ; число цветов
        ld      a, 0                ; страница палитры (0 = отображаемая)
        ld      b, #FF              ; PAL-mask = все 8 бит
        ld      c, Bios.SetPalette
        rst     #08
```

Подходит для разовых изменений (HUD, индикаторы). Для массовой заливки 256 цветов это медленно (BIOS внутри переключает окна, что съедает много тактов) — используй способ 2.

## Способ 2: прямая запись в VRAM через WIN3

Это **рекомендуемый путь для fade, кроссфейдов, циклического обновления всей палитры**. Маппим VRAM `#50` в `WIN3` (`#E2`, `$C000..$FFFF`), пишем регистры палитры, восстанавливаем прежнее содержимое WIN3.

### Запись одного цвета

```asm
; A = index, IXH = R8, IXL = G8, реги. C = B8 (значения уже сдвинуты << 2)
SetPalRGB:
        in      a, (#0xE2)
        ld      (.saved_win3), a

        ld      a, #0x50
        out     (#0xE2), a              ; WIN3 = VRAM #50

        ld      a, e                    ; например, E = индекс
        out     (#0x89), a              ; PORT_Y = индекс цвета

        ld      a, h                    ; R<<2
        ld      (#0xC3E0), a
        ld      a, l                    ; G<<2
        ld      (#0xC3E1), a
        ld      a, c                    ; B<<2
        ld      (#0xC3E2), a

        ld      a, #0xC0
        out     (#0x89), a              ; PORT_Y в безопасную зону

.saved_win3 EQU $+1
        ld      a, #0
        out     (#0xE2), a              ; восстановить прежнюю страницу в WIN3
        ret
```

### Запись всей палитры пакетом (≤ 1 кадра 50 Гц)

```asm
; HL = указатель на 256 × {R6, G6, B6}  (по 3 байта, значения 0..63)
SetPal256:
        push    ix
        in      a, (#0xE2)
        ld      (.saved_win3), a

        ld      a, #0x50
        out     (#0xE2), a              ; WIN3 = VRAM #50

        push    hl
        pop     ix                      ; IX = указатель на источник
        ld      e, 0                    ; счётчик индекса
        exx
        ld      b, 0                    ; 256 итераций через DJNZ
        exx
.loop:
        ld      a, e
        out     (#0x89), a              ; PORT_Y = индекс
        ld      a, 0 (ix) : add a,a : add a,a : ld (#0xC3E0), a   ; R<<2
        ld      a, 1 (ix) : add a,a : add a,a : ld (#0xC3E1), a   ; G<<2
        ld      a, 2 (ix) : add a,a : add a,a : ld (#0xC3E2), a   ; B<<2
        inc     ix : inc ix : inc ix
        inc     e
        exx
        djnz    .alt
        exx
        jr      .done
.alt:   exx
        jr      .loop
.done:
        ld      a, #0xC0
        out     (#0x89), a

.saved_win3 EQU $+1
        ld      a, #0
        out     (#0xE2), a
        pop     ix
        ret
```

Этого хватает, чтобы за один VSync (~20 мс при 50 Гц) обновить все 256 цветов. Реализация в SDCC SDK — `lib/src/video/fade_apply.s`.

> **Окно — на твой выбор.** Палитровый регистр декодируется только по младшим 10 битам адреса, поэтому VRAM `#50` можно положить в любое из `WIN0..WIN3` и писать по `$03E0`, `$43E0`, `$83E0` или `$C3E0` соответственно. Выбирай свободное окно. Единственная оговорка: если маппишь VRAM поверх `WIN0`, BIOS-ROM временно скрыт вместе с IM1-вектором `$0038` — на этот период обязательно `DI`. Для `WIN1..WIN3` запрет прерываний не требуется.

## Чтение палитры

Аппаратный палитровый регистр **читается** через тот же путь (WIN3 + `$C3E0..$C3E2` при `PORT_Y = index`), но на практике почти все программы хранят теневую копию в RAM и не читают железо — это проще и не требует DI/маппинга. SDK хранит копию палитры в массиве `video_rgb6_t [256]` и обновляет её одновременно с записью в VRAM.

## Стандартные палитры

### Палитра ZX Spectrum (первые 16 цветов)

```c
static const video_rgb8_t zx_palette[16] = {
    { 0,  0,  0},  { 0,  0, 42},  {42,  0,  0},  {42,  0, 42},
    { 0, 42,  0},  { 0, 42, 42},  {42, 42,  0},  {42, 42, 42},
    { 0,  0,  0},  { 0,  0, 63},  {63,  0,  0},  {63,  0, 63},
    { 0, 63,  0},  { 0, 63, 63},  {63, 63,  0},  {63, 63, 63},
};
```

### Серая градация 256 оттенков

```c
video_rgb8_t gray[256];
for (u16 i = 0; i < 256; i++) {
    u8 v = i >> 2;            // 6-битный уровень
    gray[i] = (video_rgb8_t){ v, v, v };
}
video_setpal256_fast(gray);
```

## Палитровые эффекты

### Цветовой циклинг (один-два цвета)

Менять 1–2 элемента палитры на каждом VSync — допустимо через `bios_setpal()`, оверхед мал:

```c
u8 cycle = 0;
while (running) {
    video_vsync();
    bios_setpal(5, cycle, 63 - cycle, 0);   // цвет 5: красно-зелёная радуга
    cycle = (cycle + 1) & 63;
}
```

### Fade in/out всей палитры

Через **способ 2** (прямая запись в VRAM через WIN3, без `DI`):

1. Сохрани целевую палитру в RAM как `video_rgb8_t src[256]`.
2. На каждом шаге собери LUT `lut[64]`, где `lut[c] = c * step / FADE_STEPS`.
3. Прогоняй `SetPal256` с `(R,G,B) = (lut[src[i].r], lut[src[i].g], lut[src[i].b])`.

Готовая реализация — `include/sprinter/fade.h` + `lib/src/video/fade.c` + `lib/src/video/fade_apply.s` в SDK. Один шаг укладывается в кадр 50 Гц вместе с PT3-плеером.

## Ключевые моменты

> * Палитра — это **VRAM-страница `#50`**, регистры по смещению `$3E0..$3FF` каждой строки.
> * `PORT_Y` (`#89`) выбирает индекс цвета (= номер строки VRAM). Порт **write-only**: `IN` возвращает CBL, а не текущий Y.
> * Байты палитры: `[+0]=R, [+1]=G, [+2]=B`.
> * 8 страниц палитры с шагом 4 байта; страница 0 (`$3E0`) — отображаемая.
> * **CPU-окно неважно**, важны только младшие 10 бит адреса. На практике маппим VRAM `#50` в **WIN3**, чтобы не трогать BIOS в WIN0.
> * После операции — `out (#89), #C0` (безопасная зона PORT_Y).
> * Для разовых изменений — `BIOS #A4`; для массовых fade/cycling — прямая запись через WIN3.
