# 5.8 Текстовый режим 80×32

> **Навигация:** [← 5.7 Double buffering](07_double_buffer.md) | [Оглавление](../README.md) | [5.9 Примеры графики →](09_examples.md)

---

## Что это

Текстовый режим Sprinter — это **аппаратный режим видеоконтроллера**. FPGA (`VIDEO2.TDF`) имеет отдельную схему адресации для текстового режима (`VCM[1..0] = 3`), в которой видеоконтроллер самостоятельно:

1. Читает **код символа** и **атрибут** из видеопамяти (VRAM).
2. По коду символа обращается к **знакогенератору** (шрифт), загруженному в VRAM при инициализации BIOS.
3. Формирует пиксели каждой растровой строки символа.

Программа пишет коды символов и атрибуты непосредственно в VRAM — видеоконтроллер растеризует их аппаратно, без участия CPU. Это принципиально быстрее, чем попиксельная отрисовка текста в графическом режиме.

### Роль BIOS

BIOS при инициализации **загружает знакогенератор** (шрифт 256 символов × 8 байт) в выделенную область VRAM. После этого видеоконтроллер работает автономно — CPU только записывает коды и атрибуты.

DSS/BIOS API (`RST #08` / `RST #10`) — удобная обёртка для записи в VRAM, но **прямой доступ к видеопамяти также возможен** и даёт максимальную скорость вывода (см. раздел «Прямой доступ» ниже).

## Характеристики

| Параметр | Значение |
|---------|---------|
| Сетка | **80 столбцов × 32 строки** (2 560 позиций); также 40×32 |
| Шрифт | 8 × 8 пикселей, 256 символов (псевдографика CP866/CP437) |
| Пиксельное разрешение | 80 × 8 = **640** по горизонтали, 32 × 8 = **256** по вертикали |
| Цвет символа (INK) | 4 бита → **16** цветов |
| Цвет фона (PAPER) | 3 бита → **8** цветов |
| Мерцание (FLASH) | бит 7 атрибута — мигает **только глиф** (INK), фон не меняется |
| Данные в VRAM на позицию | `MODE0` + код символа + атрибут + `MODEX` (см. ниже) |
| Знакогенератор | 256 × 8 = 2048 байт на слот; слотов несколько (по умолчанию `#1B`) |
| Прокрутка | через `Dss.Scroll #55` или прямой LDIR по VRAM |

## Знакоместо: состав 4-байтового слота

Для обычного прикладного кода текстовый экран выглядит как массив пар:

```text
sym0, atr0, sym1, atr1, sym2, atr2, ...
```

Но на уровне видеосистемы одно знакоместо хранится как **4-байтовый слот**.
Согласно `ARHITECT.TXT`, на каждый квадрат 8×8 в VRAM приходятся:

- **2 байта режима**
- **2 байта данных режима**

Для текстового знакоместа это выглядит так:

| Смещение | Имя | Назначение |
|----------|-----|------------|
| `+0` | `MODE0` | основной байт режима знакоместа |
| `+1` | `SYM` | код символа |
| `+2` | `ATTR` | атрибут символа |
| `+3` | `MODEX` | дополнительный байт режима знакоместа |

Это относится к **знакоместной видеосистеме Sprinter**. Она шире, чем
собственно текстовый режим, и включает:

- текстовый режим `80×32` и `40×32`;
- смешанные знакоместные режимы;
- внутренние типы квадратов `ZX-40`, `ZX-80`, `G256-8`, `G16-16`, `BORDER`,
  `BLANK`.

Классический ZX-экран `6912` байт является отдельным режимом совместимости.
См. [5.2 ZX режим](02_zx_mode.md).

### `MODE0`: основной байт режима

Подтверждённые значения по `VIDEO2.TDF`, `BIOS_FN.TXT` и BIOS-таблицам:

| Биты | Назначение | Влияние |
|------|------------|---------|
| `[3:0]` | младшая часть выбора ZG / палитры | в тексте — часть номера знакогенератора; в графике — палитра |
| `4` | `text-like / graphic-like` | `1` = текстово-совместимое знакоместо, `0` = графическое |
| `5` | ширина знакоместа | `0` → 80×32 (8 px), `1` → 40×32 (16 px) |
| `[7:6]` | старшая часть выбора ZG / режим | в тексте дополняет номер знакогенератора; `%11` в `[7:4]` — `BORDER` |

Для стандартного текстового окна DSS: `MODE0 = #1B` (`%0001'1011`) = текст + 80 колонок + слот ZG `#1B`.

На практике `MODE0` определяет:

- относится ли знакоместо к текстово-совместимому или графическому классу;
- как интерпретировать байты `SYM` и `ATTR`;
- какой знакогенератор или палитру использовать;
- какую геометрию имеет знакоместо.

### `MODEX`: дополнительный байт режима

В BIOS-описании окна этот байт называется `EXT MODE` (`IX+5`).

Подтверждённый флаг:

| Бит | Назначение |
|-----|------------|
| `0` | spectrum screen addressing |

То есть `MODEX` включает дополнительные варианты адресации и интерпретации
знакоместа. Для обычного текстового окна этот байт обычно выставляет BIOS, и
прикладной код его не меняет.

### `SYM`: байт символа

`SYM` — это индекс в знакогенераторе. Видеоконтроллер использует его для
выбора 8 строк растра символа.

Именно поэтому изменение `SYM` меняет отображаемый символ, но не цвет.

### `ATTR`: байт атрибута (CGA-формат)

Формат **не** «4+4 как у ZX». BIOS и DSS используют нотацию CGA/VGA
(`COLORS.CGA` в `standart_colors.inc`, см. также `programming_guide/video.md`):

```text
ATTR = %FPPPIIII
```

| Биты | Поле | Диапазон | Константа |
|------|------|----------|-----------|
| `[3:0]` | `INK` — цвет глифа | 0–15 | `COLORS.CGA.INK.*` |
| `[6:4]` | `PAPER` — цвет фона | 0–7 | `COLORS.CGA.PAPER.*` (= ink × 16) |
| `7` | `FLASH` — мерцание глифа | 0/1 | `COLORS.CGA.FLASH` (`#80`) |

При `FLASH=1` видеоконтроллер периодически подменяет цвет **пикселей глифа**
(фаза `CTF4` в `VIDEO2.TDF`); фон (`PAPER`) не меняется. Если обе фазовые
половины палитры для данного атрибута совпадают, мигания не видно
(`SP2000.inc`). Яркого фона в атрибуте нет: `PAPER` занимает только 3 бита.

Примеры:

| Байт | Разбор | Вид |
|------|--------|-----|
| `#0F` | FLASH=0, PAPER=0, INK=15 | белый на чёрном |
| `#1F` | PAPER=1 (синий), INK=15 | белый на синем |
| `#70` | PAPER=7, INK=0 | чёрный на светло-сером (без мигания) |
| `#F0` | **FLASH=1**, PAPER=7, INK=0 | то же, но глиф **мигает** |
| `#80+#10+#04` = `#94` | FLASH + PAPER.BLUE + INK.RED | мигающий красный на синем (kernel panic DSS) |

```asm
; Константы из Shared_Includes/constants/standart_colors.inc
; COLORS.CGA.FLASH      = #80
; COLORS.CGA.INK.RED    = #04
; COLORS.CGA.PAPER.BLUE = #10
        ld      e, COLORS.CGA.FLASH + COLORS.CGA.PAPER.BLUE + COLORS.CGA.INK.RED
```

> Не путать с графическим 640×256×16, где нибблы действительно `PAPER[7:4]|INK[3:0]`
> без отдельного FLASH (см. [5.4](04_mode2_640.md)).

### Практическое правило

При обычном текстовом выводе меняются:

- `SYM` — код символа;
- `ATTR` — цвет и опционально FLASH.

`MODE0` и `MODEX` обычно выставляет BIOS при открытии окна. `MODE0` нужно трогать,
если вы **переключаете знакогенератор на ячейку** (курсор DSS/FM/ui_lib) или
собираете смешанный экран.

## Аппаратная схема работы

```
┌──────────┐       ┌───────────────────────────────────┐
│   CPU    │──────►│            VRAM                    │
│ (Z80)    │ пишет │  ┌─────────┐  ┌───────────────┐  │
└──────────┘ коды/ │  │ Символы │  │ Знакогенератор│  │
             атриб.│  │ + Атриб.│  │ (шрифт 2 КБ) │  │
                   │  └────┬────┘  └───────┬───────┘  │
                   └───────┼───────────────┼──────────┘
                           │               │
                    ┌──────▼───────────────▼──────┐
                    │     Видеоконтроллер         │
                    │     (VIDEO2.TDF)             │
                    │                              │
                    │ 1. Читает код символа        │
                    │ 2. Индексирует знакогенератор│
                    │ 3. Читает атрибут (INK/PAPER/FLASH)│
                    │ 4. Формирует пиксели 8×8     │
                    └──────────┬───────────────────┘
                               │
                          Видеосигнал
```

Из `VIDEO2.TDF` — формирование адреса в текстовом режиме:

```
; VCM case 3 (текстовый режим):
VLA[].d = (DIR_PORT3, CTH[5..0], CT5, VCC, VCC, CTV[8..3], GND, GND);
```

Где:
- `DIR_PORT3` — бит выбора страницы (double buffer)
- `CTH[5..0]` — горизонтальный счётчик (позиция столбца, 0–79)
- `CTV[8..3]` — вертикальный счётчик (позиция строки, 0–31)
- `CT5` — бит строки внутри символа (0–7, для индексации знакогенератора)

Цвет формируется из атрибута аппаратно. В текстовом режиме (`MODE0[4]=1`)
в индекс палитры уходит **весь** байт атрибута (включая FLASH), плюс бит
пикселя глифа и фаза мерцания `CTF4`:

```
; VIDEO2.TDF — выбор цвета:
WHEN B"1X" => BRVA[7..0] = DCOL[];     ; текст: полный ATTR → адрес палитры
; RBRVA[10..8] = (1, CTF4, pixel_bit)  ; банк: бумага/чернила × фаза FLASH
WHEN B"01" => BRVA = PAPER-ниббл;      ; (графика 16цв.)
WHEN B"00" => BRVA = INK-ниббл;        ; (графика 16цв.)
```

## Структура видеопамяти в текстовом режиме

### Поле графики и положение окна

Видео-ОЗУ Sprinter представляется как **единое поле графики 1024×256 точек** (из документации Peters Plus: `BIOS_FN.TXT`). В знакоместах это **128 столбцов × 32 строки** (по 8×8 пикселей каждое).

На экран выводится только часть этого поля. Текстовое окно 80×32 — это «окно» (viewport) внутри полного поля, расположенное по координатам, заданным при открытии (параметры `IX+6`, `IX+7` дескриптора окна).

```
Поле графики 128×32 знакомест (1024×256 точек)
┌──────────────────────────────────────────────┬──────────────────┐
│                                              │                  │
│       Текстовое окно 80×32                   │   Невидимая      │
│       (то, что видно на экране)              │   область        │
│                                              │   (столбцы       │
│       столбцы 0..79                          │    80..127)      │
│                                              │                  │
│                                              │                  │
└──────────────────────────────────────────────┴──────────────────┘
```

**Куда деваются оставшиеся 48 столбцов (80..127)?** Они физически существуют в VRAM, но не отображаются на экране. Эта область занята:

- **Знакогенераторами.** Каждый знакогенератор занимает 8 столбцов по X (см. раздел «Знакогенератор в поле графики» ниже). До 16 знакогенераторов × 8 столбцов = 128 столбцов — ровно всё поле.
- **Ячейками синхронизации и гашения.** Видеоконтроллер для каждого «квадрата» (знакоместа) хранит в VRAM **байт режима** (`MODE0`). Ячейки за пределами видимой области могут иметь режим **BORDER** (вывод цвета бордюра) или **BLANK** (гашение — чёрный). Эти ячейки участвуют в формировании видеосигнала — бордюра и синхроимпульсов. **Изменять их не следует** — это может привести к нарушению синхронизации или артефактам на экране.

Из `VIDEO2.TDF`:
```
; MODE0[7..4] == %1111 → режим BORDER: вместо символа выводится цвет бордюра
IF DFF((MODE0[7..4] == 15), WR_PIC,,) THEN
    DCOL[].d = (%00, BRD[2..0], BRD[2..0]);    ; цвет бордюра

; BLANK: сигнал гашения обнуляет атрибут
DCOL[].clrn = !BLANK;                           ; чёрный при гашении
```

> **Потенциально** разрешение текстового режима можно увеличить за пределы 80×32 — например, до 96×32 или даже 128×32 — за счёт сужения бордюра. Однако это требует перенастройки BIOS (изменение дескриптора окна и режимов ячеек в VRAM) и не является штатной возможностью. Стандартная конфигурация DSS: окно 80×32 с координатой `(0, 0)` поля графики.

### Адресация: координаты → позиция в памяти

Для программного доступа к текстовому экрану (через BIOS-функции или при работе с буфером `WinCopy`/`WinRest`) используется **линейная адресация**:

```
позиция = столбец + строка × 80
```

Где `столбец` = 0..79, `строка` = 0..31.

Каждая позиция хранит **пару: код символа + атрибут** (по 1 байту каждый). В буфере `WinCopy`/`WinRest` данные идут в формате IBM PC:

```
sym0, atr0, sym1, atr1, sym2, atr2, ...
```

Сначала все пары первой строки (80 пар = 160 байт), затем второй строки и т. д. Общий размер буфера окна 80×32 = **5120 байт** (2560 символов + 2560 атрибутов).

### Аппаратная адресация (VLA)

Видеоконтроллер формирует 18-битный адрес VRAM (`VLA`) из счётчиков развёртки. Для текстового режима (VCM case 3) из `VIDEO2.TDF`:

```
VLA[17..0] = (DIR_PORT3, CTH[5..0], CT5, VCC, VCC, CTV[8..3], GND, GND)
```

Разбор по битам:

```
Бит VLA  Источник         Назначение
──────────────────────────────────────────────────
  17     DIR_PORT3         Выбор страницы (double buffer)
  16..11 CTH[5..0]         Номер столбца (0..79)
  10     CT5               Строка растра внутри символа (для знакогенератора)
   9..8  VCC, VCC          Константы = %11
   7..2  CTV[8..3]         Номер строки (0..31)
   1..0  GND, GND          Константы = %00
```

Из этого следует аппаратный адрес символа в VRAM:

```
VRAM_адрес = (страница << 17) | (столбец << 11) | (%11 << 8) | (строка << 2)
```

Или проще: видеоконтроллер обращается к VRAM по «разбросанным» адресам — столбец в старших битах, строка в младших. Это **не** линейный буфер типа `строка × 80 + столбец`, а аппаратная раскладка, оптимизированная под счётчики развёртки.

### Знакогенератор в поле графики

Знакогенератор (шрифт) **физически хранится в том же поле графики** VRAM. Его положение определяется номером в описателе окна (биты `IX+4`):

```
X_зг = (8 × номер_зг[3..0]) .. (8 × номер_зг[3..0] + 7)   ; 8 знакомест по X
Y_зг = 0 .. 31                                                ; все строки по Y
```

Если знакогенератор №0, он занимает столбцы 0–7 поля графики. Текстовое окно 80×32 занимает столбцы 0–79 — они **пересекаются**. Именно поэтому знакогенератор «встроен» в экранные данные: его битовые образы символов лежат в тех же VRAM-ячейках, которые видеоконтроллер интерпретирует и как данные шрифта.

> **Практический вывод:** при прямой записи в VRAM не записывайте в область, занятую знакогенератором — иначе «испортите» шрифт. Стандартный знакогенератор №0 занимает первые 8 столбцов, поэтому символы с координатами столбцов 0–7 содержат данные шрифта.

### Пример: расчёт адреса для WinCopy-буфера

```asm
; Вычислить смещение символа (col, row) в буфере WinCopy/WinRest
; Вход: D = row (0..31), E = col (0..79)
; Выход: HL = смещение в буфере (sym байт); HL+1 = атрибут

CalcBufOffset:
        ld      h, 0
        ld      l, d                ; L = row
        ; HL = row × 80: row × 64 + row × 16
        add     hl, hl              ; × 2
        add     hl, hl              ; × 4
        add     hl, hl              ; × 8
        add     hl, hl              ; × 16
        ld      b, h
        ld      c, l                ; BC = row × 16
        add     hl, hl              ; × 32
        add     hl, hl              ; × 64
        add     hl, bc              ; HL = row × 80
        ld      b, 0
        ld      c, e                ; BC = col
        add     hl, bc              ; HL = row × 80 + col
        add     hl, hl              ; × 2 (каждая позиция = 2 байта: sym + atr)
        ret
        ; HL = смещение в буфере
        ; (buf + HL) = код символа
        ; (buf + HL + 1) = атрибут
```

### Пример: запись символа через BIOS `Win_Put_Sym` (`#B5`)

Семантика `B` (актуальный BIOS, `FUNC_LOW_PRINT.ASM`, правка 31/03/2025):

| `B` | Действие |
|-----|----------|
| `0` | только символ (`SYM`), атрибут и `MODE0` не трогать |
| `1` | символ + атрибут, `MODE0`/шрифт не менять (`WIN_PUT_SYM.NoChangeZG`) |
| `≥ 2` | символ + атрибут + записать `MODE0 = B` (выбор знакогенератора) |

```asm
; Символ + атрибут, шрифт ячейки не менять
        xor     a                   ; ID окна = 0
        ld      d, 5                ; row
        ld      e, 10               ; col
        ld      l, 'A'              ; символ
        ld      h, #0F              ; ATTR: белый на чёрном
        ld      b, 1                ; не менять ZG
        ld      c, #B5              ; Win_Put_Sym
        rst     #08

; Тот же символ, но ячейка рисуется знакогенератором курсора #5B
        xor     a
        ld      d, 5
        ld      e, 10
        ld      l, 'A'
        ld      h, #0F
        ld      b, #5B              ; MODE0 = CURSOR_ZG (подчёркивание)
        ld      c, #B5
        rst     #08
```

`Win_Get_Sym` (`#B4`): вход `A` = окно, `DE` = row/col; выход `HL` = sym/attr,
`B` = текущий `MODE0` (в т.ч. номер/биты знакогенератора).

## Включение текстового режима

При старте из DSS текстовый режим обычно уже активен. Если нужно переключиться явно:

```asm
; Коды режимов для Dss.SetVMod (#50):
;   #02 = текстовый 40×32 (16 цветов)
;   #03 = текстовый 80×32 (16 цветов)  ← стандартный
;   #81 = графика 320×256, 256 цветов
;   #82 = графика 640×256, 16 цветов

; 1. Сохранить текущий режим
        ld      c, #51          ; Dss.GetVMod
        rst     #10
        ; A = код текущего режима, B = видеостраница
        ld      (saved_mode), a
        ld      (saved_page), b

; 2. Включить текстовый режим 80×32
        ld      a, #03          ; #03 = текстовый 80×32
        ld      b, 0            ; видеостраница 0
        ld      c, #50          ; Dss.SetVMod
        rst     #10

        ; ... работа в текстовом режиме ...

; 3. Восстановить исходный режим
        ld      a, (saved_mode)
        ld      b, (saved_page)
        ld      c, #50          ; Dss.SetVMod
        rst     #10

saved_mode:     db 0
saved_page:     db 0
```

## Два способа вывода текста

### Способ 1: через DSS/BIOS API (удобно)

Все функции — через `RST #10`, номер в регистре `C`:

| Код | Имя | Назначение |
|-----|-----|-----------|
| `#52` | `Locate` | Установить позицию курсора (D = row, E = col) |
| `#53` | `Cursor` | Получить позицию курсора (→ D, E) |
| `#55` | `Scroll` | Прокрутить окно (B = направление, D/E = поз., H/L = размер) |
| `#56` | `Clear` | Очистить окно (A = символ, B = атрибут, D/E = поз., H/L = размер) |
| `#57` | `RdChar` | Прочитать символ в позиции (→ A = символ, B = атрибут) |
| `#58` | `WrChar` | Записать символ с атрибутом (A = символ, B = атрибут, D/E = поз.) |
| `#59` | `WinCopy` | Скопировать окно в буфер |
| `#5A` | `WinRest` | Восстановить окно из буфера |
| `#5B` | `PutChar` | Печать символа (с обработкой CR, LF, Tab и автоскроллом) |
| `#5C` | `PChars` | Печать ASCIIZ-строки (HL = адрес строки) |

### Способ 2: прямой доступ к VRAM (быстро)

Программа может записывать коды символов и атрибуты **непосредственно в VRAM** — видеоконтроллер отобразит их аппаратно. Это значительно быстрее, чем вызовы BIOS.

#### Организация VRAM в текстовом режиме

Источник: `sprinter_docs/main_ram/video_area.md`, `ARHITECT.TXT`, BIOS `EXP_LP2.ASZ`.

В режиме 80×32 экран аппаратно делится на **40 «аппаратных столбцов»** (a = 0..39), каждый из которых содержит два текстовых символа (левый — Line1, правый — Line2). Записью в VRAM управляют:

| Компонент | Что задаёт | Формула (экран A) |
|-----------|-----------|------------------|
| **PORT_Y** (порт `#89`) | Номер «графической линии» = **текстовый столбец** | `col + 1` |
| **Адрес HL** (окно WIN3) | **Строка и позиция байта** | `#C301 + row × 4` (Mode1) |

> **PORT_Y = col + 1** задаёт «графическую линию» VRAM, соответствующую тексовому столбцу `col`. Аппаратная формула: `Line = 1 + 2·(col/2) + (col mod 2) = col + 1`.

Каждая текстовая позиция `(col, row)` занимает 4-байтовый слот в VRAM. Для
обычного текстового окна из этих четырёх байтов программа обычно использует
только два средних: символ и атрибут.

```
Смещение  Байт   Назначение
─────────────────────────────────────────────────
LA + 0    Mode0  Служебный байт режима знакоместа
LA + 1    Sym    Код символа (char code)   ← HL = #C301 + row × 4
LA + 2    Attr   Атрибут (INK/PAPER)       ← HL + 1 = #C302 + row × 4
LA + 3    ModeX  Дополнительный байт режима знакоместа
```

где `LA = #0300 + row × 4`, и в окне `WIN3 = #C000..#FFFF` адрес получается
как `#C300 + row × 4 + смещение`.

Для обычного текста главное помнить следующее:

- `#C301 + row×4` — байт символа;
- `#C302 + row×4` — байт атрибута;
- `#C300` и `#C303` принадлежат служебному описанию знакоместа.

Окно записи: **WIN3** (`EmmWin.P3` = порт `#E2`) со страницей `#50`.

```
Экран A, col 0..79, row 0..31:

  PORT_Y  =  col + 1              col=0 → 1,  col=1 → 2,  ..., col=79 → 80
  HL      =  #C301 + row × 4      row=0 → #C301, row=1 → #C305, ..., row=31 → #C37D
  символ  →  OUT (#89), PORT_Y  :  LD (HL), char           (→ Mode1)
  атрибут →  (тот же PORT_Y)    :  INC L : LD (HL), attr   (→ Mode2)
             DEC L (вернуть HL к Mode1)

Экран B (теневой):
  PORT_Y  =  (col + 1) | #80      col=0 → #81, col=1 → #82, ..., col=79 → #D0
  HL      =  #C301 + row × 4      (то же самое)
```

Переход к следующей строке: `INC L : INC L : INC L : INC L` (L += 4, от Mode1 к следующему Mode1).

#### Вывод одного символа

```asm
; Вход: D = row (0..31), E = col (0..79), B = символ, C = атрибут (экран A)
DirectPutChar:
        in      a, (#E2)
        push    af                  ; сохранить текущую страницу WIN3

        ld      a, #50
        out     (#E2), a            ; WIN3 → VRAM (страница #50)

        ; PORT_Y = col + 1  (выбор столбца)
        ld      a, e
        inc     a                   ; col + 1
        out     (#89), a            ; PORT_Y

        ; HL = #C301 + row*4  (Mode1 = код символа)
        ld      a, d
        add     a, a                ; row × 2
        add     a, a                ; row × 4
        ld      l, a
        inc     l                   ; → #C301 + row*4 (Mode1, не Mode0!)
        ld      h, #C3              ; HL = #C301 + row*4

        ld      (hl), b             ; символ (Mode1)
        inc     l
        ld      (hl), c             ; атрибут (Mode2)

        pop     af
        out     (#E2), a            ; восстановить WIN3
        ret
```

#### Вывод строки

Для строки текста PORT_Y нужно менять для каждого столбца (+2 за символ), а HL остаётся той же строкой. BIOS использует теневые регистры (`EXX`) для хранения двух контекстов. Самый практичный подход для прикладной программы — цикл через DSS `WrChar`:

```asm
; D = row (0..31), E = col (0..79), HL = адрес ASCIIZ-строки, C = атрибут
PrintString:
        ld      a, (hl)
        and     a
        ret     z                   ; конец строки
        ld      b, a                ; символ
        push    hl
        push    de
        push    bc
        ld      a, b
        ld      b, c                ; атрибут в B
        ld      c, #58              ; Dss.WrChar
        rst     #10
        pop     bc
        pop     de
        inc     e                   ; следующий столбец
        pop     hl
        inc     hl
        jr      PrintString
```

Для максимальной скорости блочного вывода (без DSS) — используйте цикл с прямым доступом, копируя паттерн BIOS `LP_PRINT_SY1` с `EXX` и `OUT (C), D`.
```

Через BIOS (`RST #08`, функция `CMD_PRINT_LINE3 = #87`) тот же вывод:

```asm
; Вывод через BIOS (из LION.ASZ)
        ld      hl, text_data       ; адрес строки
        ld      b, line_length      ; длина
        ld      e, #29              ; атрибут (цвет)
        ld      d, #0D              ; delimiter (CR)
        ld      c, #87              ; BIOS LP_PRINT_LN3
        rst     #08
```

## Атрибут символа (сводка)

```text
%F P P P I I I I
 │ └─┬─┘ └──┬──┘
 │   │      └─ INK   0..15  (COLORS.CGA.INK.*)
 │   └──────── PAPER 0..7   (COLORS.CGA.PAPER.* = ink×16)
 └──────────── FLASH 0/1    (COLORS.CGA.FLASH = #80)
```

16 цветов INK и 8 цветов PAPER берутся из текстовых страниц палитры
(см. [5.5 Палитра](05_palette.md)). По умолчанию это CGA-набор из
`standart_colors.inc`.

| Байт | Смысл |
|------|--------|
| `#0F` | белый на чёрном |
| `#1F` | белый на синем (`PAPER.BLUE + INK.WHITE`) |
| `#17` | светло-серый на синем |
| `#3E` | жёлтый на голубом (часто «selected» в FM/ftpclient) |
| `#70` | чёрный на светло-сером (**без** мигания) |
| `#F0` | то же + **FLASH** — глиф мигает |
| `#80+#04` | мигающий красный на чёрном |

### Пример: мигающий текст через DSS

```asm
; Напечатать мигающую строку (красный на синем)
        ld      d, 10
        ld      e, 5
        ld      c, #52              ; Locate
        rst     #10

        ld      a, '!'
        ld      b, COLORS.CGA.FLASH + COLORS.CGA.PAPER.BLUE + COLORS.CGA.INK.RED
        ld      d, 10
        ld      e, 5
        ld      c, #58              ; WrChar
        rst     #10
```

Аппарат мигает сам (фаза `CTF4` в FPGA) — CPU крутить таймер не обязан.
Курсорная «каретка» — другой механизм: программная смена `MODE0` на ячейке
при том же `SYM`/`ATTR` (см. раздел «Курсор» и знакогенераторы).

## Курсор

```asm
; Установить позицию
        ld      d, <row>            ; 0..31
        ld      e, <col>            ; 0..79
        ld      c, #52
        rst     #10

; Получить позицию
        ld      c, #53
        rst     #10
        ; D = row, E = col
```

### Как выглядит «мигающий курсор»

На экране нет отдельной картинки-курсора. В ячейке по-прежнему лежит обычный
символ (буква, пробел и т.д.) и его цвет. Меняется только то, **каким шрифтом**
эта ячейка рисуется.

В системе заранее лежат три варианта шрифта:

- обычный — буква выглядит как обычно;
- «с чертой» — у того же кода символа внизу дорисовано подчёркивание (каретка);
- «блок» — тот же символ, но инвертированный (залитая каретка в режиме Insert).

Раз в несколько тиков прерывания программа снова записывает **ту же** ячейку:
то с обычным шрифтом, то со шрифтом «с кареткой». Символ и цвет не трогают —
меняется только номер знакогенератора в байте режима ячейки (`MODE0`: `#1B` ↔
`#5B` или `#9B`). Отсюда и мигание: железо просто перерисовывает глиф другим
шрифтом.

Это не бит `FLASH` в атрибуте: `FLASH` мигает цветом глифа аппаратно, а курсор
shell — обычный программный цикл «показать каретку / убрать каретку».

В командной оболочке DSS этим занимается обработчик клавиатуры. В своём
приложении то же нужно делать самому: по таймеру читать ячейку, записать её
обратно с другим номером шрифта (так делают FM и `ui_lib`).

## Спецсимволы и управление

Функции `PutChar` (`#5B`) и `PChars` (`#5C`) обрабатывают управляющие коды:

| Код | Действие |
|-----|---------|
| 13 (CR) | Возврат каретки (курсор в колонку 0) |
| 10 (LF) | Перевод строки (row++) |
| 9 (Tab) | Табуляция до следующей границы 8 |
| ≥ 32 | Обычный символ, печать с инкрементом колонки |

При переходе за правый край — автоперенос; при достижении низа — автопрокрутка.

## Знакогенераторы: загрузка, слоты и переключение

На экране одновременно могут жить **несколько** шрифтов. Каждая текстовая
ячейка через байт `MODE0` выбирает, каким знакогенератором её рисовать.
DSS при `SetVMod #03` открывает окно с `MODE = %0001'1011` (`#1B`) —
это и есть «системный» слот (`NORM_ZG` в `KEYINTER.ASM`).

### Биты `MODE0` в текстовом окне

| Биты | Роль |
|------|------|
| `4` | `1` = текстовое знакоместо |
| `5` | `0` = 80×32 (ячейка 8×8), `1` = 40×32 (ячейка 16×8) |
| `[3:0]`, `[7:6]` | выбор слота знакогенератора |

Типичные значения (DSS / ui_lib / FM):

| Код | Имя | Назначение |
|-----|-----|------------|
| `#1B` | `NORM_ZG` | обычный системный шрифт |
| `#5B` | `CURSOR_ZG` | курсор-подчёркивание (нижние 2 линии `#FF`) |
| `#9B` | `INS_CUR_ZG` | курсор-блок (инвертированный шрифт) |
| `#19` / `#1A` | FM soft-cursor | аналогичный приём в File Manager |

При смене шрифта на ячейке **сохраняйте бит 5** (40/80), как делает DSS:

```asm
; B = MODE0 из Win_Get_Sym
        ld      a, %0010'0000
        and     b                   ; выделить bit5 (40/80)
        or      #5B                 ; новый угол ZG
        ld      b, a
```

### BIOS API

| Код | Имя | Назначение |
|-----|-----|------------|
| `#B6` | `Win_Set_ZG` | записать 2048 байт шрифта в слот VRAM |
| `#B8` | `Win_Get_ZG` | скопировать **встроенный** системный шрифт BIOS в буфер |
| `#B5` | `Win_Put_Sym` | символ/атрибут/`MODE0` в ячейку |
| `#B4` | `Win_Get_Sym` | прочитать символ/атрибут/`MODE0` |

> `Win_Get_ZG` **не читает VRAM**. Он делает `LDIR` из `ZG_ADDRESS` (вшитый
> `FONT.ASM` в BIOS) в буфер `DE`. Это «эталонный» системный шрифт — удобно как
> база для курсорных/пользовательских слотов. Текущее содержимое произвольного
> слота в VRAM API не отдаёт — его нужно читать вручную или держать копию.

#### `Win_Set_ZG` (`#B6`)

**Вход:** `A` = номер слота знакогенератора, `DE` = адрес 2048 байт данных,
`C = #B6`, `RST #08`.

```asm
; Загрузить свой шрифт в слот #1B (системный текстовый)
        ld      a, #1B
        ld      de, my_font
        ld      c, #B6
        rst     #08
        ret

my_font:
        ds      2048                ; 256×8
```

#### `Win_Get_ZG` (`#B8`)

**Вход:** `DE` = буфер ≥ 2048 байт, `C = #B8`, `RST #08`.

```asm
        ld      de, font_buf
        ld      c, #B8
        rst     #08
```

### Формат глифа

256 символов × 8 байт. Старший бит байта — левый пиксель строки:

```
; 'A' (#41):
        db  %00011000   ; #18
        db  %00100100   ; #24
        db  %01000010   ; #42
        db  %01111110   ; #7E
        db  %01000010
        db  %01000010
        db  %01000010
        db  %00000000
```

### Способ 1: перезагрузить системный шрифт через BIOS

```asm
; Вернуть слот #1B к встроенному шрифту BIOS
ReloadSystemFont:
        ld      de, font_buf
        ld      c, #B8              ; эталон из BIOS
        rst     #08
        ld      a, #1B
        ld      de, font_buf
        ld      c, #B6
        rst     #08
        ret

font_buf:   ds 2048
```

### Способ 2: сделать курсорный шрифт (как DSS / FM)

Паттерн из `Estex-DSS/DSS/KEYINTER.ASM` (`SETUP_CURSORS`) и
`FM/LOAD.ASM` (`setup_znak`):

1. `Win_Get_ZG` → буфер.
2. Модифицировать глифы (нижние 2 линии = `#FF` для подчёркивания, либо `CPL`
   всего шрифта для блока).
3. `Win_Set_ZG` с `A = #5B` или `#9B` (или `#19`/`#1A` в FM).
4. На нужной ячейке `Win_Put_Sym` с `B =` этим номером — символ и атрибут
   ячейки **не меняются**, меняется только то, каким шрифтом они рисуются.

```asm
; Подготовить CURSOR_ZG (#5B): системный шрифт + заливка двух нижних линий
SetupCursorFont:
        ld      de, font_buf
        ld      c, #B8
        rst     #08

        ld      hl, font_buf + (2048 - 512)
        ld      de, font_buf + (2048 - 512) + 1
        ld      bc, 511
        ld      (hl), #FF
        ldir

        ld      a, #5B              ; CURSOR_ZG
        ld      de, font_buf
        ld      c, #B6
        rst     #08
        ret
```

Мигание каретки — программное (`cursor_interrupt` → `Cursor` → `Win_Put_Sym`):
чередуются `NORM_ZG` / `CURSOR_ZG` / `INS_CUR_ZG`, код символа и атрибут ячейки
не меняются. `ui_lib` text_field делает то же с `#1B`/`#5B`.

### Способ 3: сменить шрифт одной ячейки вручную (VRAM)

Запись в `MODE0` при том же `PORT_Y`, что и для символа. Код символа —
`#C301+row×4`, атрибут — `#C302+row×4` (см. «Прямой доступ»).

```asm
; Вход: D=row, E=col, B=MODE0 (например #5B), экран A
DirectSetZG:
        in      a, (#E2)
        push    af
        ld      a, #50
        out     (#E2), a

        ld      a, e
        inc     a
        out     (#89), a            ; PORT_Y = col+1

        ld      a, d
        add     a, a
        add     a, a                ; row×4
        ld      l, a
        ld      h, #C3              ; HL → MODE0
        ld      (hl), b

        pop     af
        out     (#E2), a
        ret
```

### Способ 4: загрузить шрифт в VRAM без BIOS

`Win_Set_ZG` внутри (`FUNC_LOW_PRINT.ASM`):

1. Мапит служебную страницу в `SLOT1`, отключает ZX-screen/акселератор в
   `Port_All_Mode`.
2. `PORT_Y = (A & #0F) × 2` — «колонка» слота в поле графики.
3. Считает адрес назначения в окне из старших бит `A`, копирует `ZG_SIZE`
   (2048) байт `LDIR` из `DE`.
4. Дописывает служебную таблицу индексов символов.

Для прикладного кода надёжнее вызывать `#B6`. Прямая запись имеет смысл только
если вы повторяете ту же геометрию слотов, что BIOS (иначе текст поедет на
«чужой» шрифт или испортит видимые столбцы — знакогенератор лежит в том же
поле, что и экран, см. выше).

## Когда использовать текстовый режим

**Используйте**, если:
- Приложение — утилита, редактор, настройки, отладчик.
- Нужен быстрый вывод текста — видеоконтроллер рендерит аппаратно.
- Достаточно 80×32 сетки с 16 цветами.
- Нужна прокрутка, окна, сохранение/восстановление — через API «из коробки».
- Возможен прямой доступ к VRAM для максимальной скорости.

**Не используйте**, если:
- Нужна пиксельная графика (спрайты, линии) — тогда 320×256 или 640×256.
- Нужно более 16 одновременных цветов.

## Ключевые моменты

> - Текстовый режим — **аппаратный**: FPGA читает `SYM`/`ATTR`/`MODE0` и рендерит через знакогенератор.
> - Сетка 80×32 (или 40×32). Атрибут CGA: `FLASH[7] | PAPER[6:4] (0..7) | INK[3:0] (0..15)`.
> - Бит `FLASH` мигает глиф (`INK`); фон (`PAPER`) не меняется.
> - Несколько знакогенераторов в VRAM; ячейка выбирает слот через `MODE0` (`#1B` / `#5B` / `#9B`…).
> - `Win_Set_ZG`: `A` = слот, `DE` = 2048 байт. `Win_Get_ZG` отдаёт вшитый шрифт BIOS, не VRAM.
> - Вывод: DSS `#52`–`#5C`, BIOS `#81`–`#8E` / `#B4`–`#B6`, или прямая запись в VRAM.
> - Псевдографика CP866; `WinCopy`/`WinRest` для диалогов.
