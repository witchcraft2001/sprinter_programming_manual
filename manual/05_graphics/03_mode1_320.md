# 5.3 Режим 320×256, 8bpp

> **Навигация:** [← 5.2 ZX режим](02_zx_mode.md) | [Оглавление](../README.md) | [5.4 Режим 640×256 →](04_mode2_640.md)

---

## Характеристики

| Параметр | Значение |
|---------|---------|
| Разрешение | 320 × 256 пикселей |
| Биты на пиксель | 8 (256 цветов) |
| Формат | Индексированная палитра 256 цветов из 16 777 216 |
| Размер экрана | 320 × 256 = 81 920 байт |
| Количество страниц 16 КБ | 5 страниц (80 КБ + padding) |
| Double buffering | Да (2 экрана в VRAM) |

Это **основной режим** для нативных программ Sprinter. Он даёт лучшее соотношение: полноцветность + быстрый линейный доступ + работа с акселератором.

---

## Включение режима

`SetVMod` (функция `#50`): `A` = код режима, `B` = номер экрана (0/1), `C` = `#50`,
затем `RST #10`. Код режима **320×256×256 цветов — `#81`** (см. `Estex-DSS/DSS/API/
SetVMod.asm`; не путайте с числом «1»). Включение одного экрана:

```asm
        ld      a, #81              ; 320×256×256c
        ld      b, #00              ; экран 0
        ld      c, #50              ; Dss.SetVMod
        rst     #10
```

`GetVMod` (`#51`) возвращает `A` = текущий режим, `B` = отображаемый экран (удобно для
сохранения/восстановления при выходе).

> Для **двойной буферизации** нужно инициализировать **оба** экрана (0 и 1) — см.
> [«Двойная буферизация»](#двойная-буферизация) ниже. Полный обзор режима, кодов и
> дескрипторов — [5.1 Обзор видеосистемы](01_video_overview.md).

> Существует и прямой порт режима `ALL_MODE` (`#C3`, см. [5.1](01_video_overview.md#ключевые-порты-видеоконтроллера)),
> но штатный и переносимый путь — через DSS `SetVMod`.

## Адресация пикселей (CPU-view)

VRAM режима **не отображается в адреса Z80 линейно**. Аппаратно физический байт
видеопамяти выбирается так (подтверждено эмулятором, см. [5.1](01_video_overview.md)):

```
физический_байт = m_vram[ PORT_Y * 1024 + (cpu_адрес & #3FF) ]
```

То есть **строку растра задаёт `PORT_Y`**, а младшие 10 бит CPU-адреса внутри окна — это
смещение в строке. Номер страницы, записанный в окно (`#50`, `#5C`…), задаёт **режим
записи** (норма / прозрачность / зеркало — см. [5.6](06_accelerator.md)), а **не** другой
регион экрана. Поэтому страницы `#51`–`#54` — это **не** «следующие части экрана»; не
мапьте их для адресации пикселей.

Практическая раскладка одной строки (страница `#50` в WIN3, `#E2`):

| CPU-адрес | Содержимое строки `PORT_Y` |
|-----------|----------------------------|
| `#C000 + x` | пиксель `(x, PORT_Y)` **буфера 0**, `x = 0..319` |
| `#C140 + x` | пиксель `(x, PORT_Y)` **буфера 1**, `x = 0..319` |
| `#C3E0…#C3FF` | регистры палитры (см. [5.5](05_palette.md)) |

Буфер 1 смещён на **320 (`#140`)** байт от буфера 0 — это «VRAM X offset» страницы 1 в
дескрипторе экрана (см. [5.1](01_video_overview.md)). Оба буфера доступны одновременно в
окне `#50`.

## Установка пикселя

```asm
; Нарисовать пиксель цвета C в координатах (X, Y) в буфере 0.
; Вход: DE = X (0..319), A = Y (0..255), C = цвет.
SetPixel320:
        push    af
        ld      a, #50
        out     (#E2), a            ; WIN3 = VRAM-страница #50
        pop     af
        out     (#89), a            ; PORT_Y = строка растра Y

        ld      hl, #C000           ; база буфера 0 (для буфера 1 => #C140)
        add     hl, de              ; HL = #C000 + X (DE = X как 16-бит!)
        ld      (hl), c             ; пиксель

        ld      a, #C0
        out     (#89), a            ; вернуть PORT_Y в невидимую зону
        ret
```

> **X — 16-битный.** `X` доходит до 319, поэтому смещение считается через 16-битный
> регистр (`DE`/`HL`). Распространённая ошибка — 8-битное вычисление смещения (например
> `x*8` для тайла через `ADD A,A`): при результате > 255 происходит заворот, и правая
> часть картинки «сворачивается» в левую. Считайте смещение в `HL` (см. «Подводные
> камни» ниже).

## Очистка экрана

Экран очищается **построчно**: для каждой строки `PORT_Y = 0..255` заполняем 320 байт
буфера. Строку выбирает `PORT_Y`, а не номер страницы.

```asm
; Заполнить буфер 0 цветом COLOR (256 строк × 320 байт).
ClearScreen320:
        ld      a, #50
        out     (#E2), a            ; WIN3 = VRAM #50
        xor     a                   ; PORT_Y = 0
.row:
        out     (#89), a
        push    af
        ld      hl, #C000
        ld      (hl), COLOR         ; первый байт строки
        ld      de, #C001
        ld      bc, 319             ; ещё 319 байт
        ldir                        ; (для скорости — акселератор, см. 5.6)
        pop     af
        inc     a
        jr      nz, .row            ; 0..255
        ld      a, #C0
        out     (#89), a            ; припарковать PORT_Y
        ret
```

> **Быстрее — через акселератор.** Два варианта:
> - **Горизонтальная заливка** (`LD C,C`): по строкам, 320 байт = две операции по 160
>   (счётчик блока 8-битный, 320 > 255) — итого 256 строк × 2.
> - **Вертикальная заливка** (`LD E,E`): заливает столбец сразу на все 256 строк (блок
>   256, помещается в 8-битный счётчик) — итого всего **320 операций** на весь экран,
>   без 256 переключений `PORT_Y`. Обычно это самый дешёвый способ очистки.
>
> См. [5.6 Акселератор](06_accelerator.md).

## Горизонтальная линия

```asm
; Линия длиной L в строке Y, начиная с X, в буфере 0.
; Вход: A = Y, DE = X (0..319), BC = L, COLOR = цвет.
HLine320:
        push    af
        ld      a, #50
        out     (#E2), a            ; WIN3 = #50
        pop     af
        out     (#89), a            ; PORT_Y = Y
        ld      hl, #C000
        add     hl, de              ; HL = #C000 + X
        ld      (hl), COLOR
        ld      d, h : ld e, l
        inc     de
        dec     bc
        ldir                        ; длинные линии — через акселератор
        ld      a, #C0
        out     (#89), a
        ret
```

## Вертикальная линия

Вертикальная линия — это **смена `PORT_Y` на каждой строке** при постоянном CPU-адресе
`#C000 + X` (а не прибавление 320 к адресу):

```asm
; Линия высотой H в столбце X, от строки Y0, в буфере 0.
; Вход: DE = X, B = Y0, C = H, COLOR = цвет.
VLine320:
        ld      a, #50
        out     (#E2), a
        ld      hl, #C000
        add     hl, de              ; HL = #C000 + X (постоянный адрес столбца)
.row:
        ld      a, b
        out     (#89), a            ; PORT_Y = строка
        ld      (hl), COLOR
        inc     b
        dec     c
        jr      nz, .row
        ld      a, #C0
        out     (#89), a
        ret
```

> Для длинных линий и заливок используйте акселератор (`LD C,C` / `LD E,E`) —
> см. [5.6 Акселератор](06_accelerator.md).

## Двойная буферизация

Оба буфера лежат в одной странице `#50` и различаются **CPU-базой**: буфер 0 — `#C000`,
буфер 1 — `#C140` (разница 320 байт). Отдельных страниц `#55`–`#59` для «второго экрана»
**нет**. Порт `#C9` (RGMOD) бит 0 выбирает отображаемый буфер; рисуем в **скрытый**.

> Перед этим **режим должен быть установлен на обоих экранах** (`SetVMod` для `B=1` и
> `B=0`) — иначе скрытый буфер при flip покажет мусор. Полный разбор и пример инициализации
> — [5.7 Двойная буферизация](07_double_buffer.md).

```asm
        ld      a, #50
        out     (#E2), a            ; WIN3 = #50 (на всё время отрисовки)

        in      a, (#C9)
        and     1                   ; 0 = виден буфер 0, 1 = виден буфер 1
        ld      hl, #C140           ; виден 0 -> рисуем в буфер 1
        jr      z, .have_base
        ld      hl, #C000           ; виден 1 -> рисуем в буфер 0
.have_base:
        ; HL = база скрытого буфера; для каждой строки выставляем PORT_Y,
        ; пиксели пишем по HL + x.
        call    DrawFrame

        call    WaitVSync           ; HALT или поллинг #FFFE.5 — см. 5.7

        in      a, (#C9)            ; flip
        xor     1
        out     (#C9), a
        ret
```

Подробнее — [5.7 Двойная буферизация](07_double_buffer.md).

## Установка палитры

Полный протокол палитры — в разделе [5.5 Палитра и порт #89](05_palette.md). Кратко:

* Палитра живёт в **VRAM `#50`**: 8 палитр-страниц по 4 байта в блоке `$3E0..$3FF` каждой
  строки. Страница 0 — по `#C3E0` (палитра буфера 0), страница 1 — по `#C3E4` (буфера 1).
* `PORT_Y` (`#89`) — индекс цвета (= номер строки VRAM). Порт **write-only**: `IN A,(#89)` возвращает регистр CBL, а не текущий Y.
* Байты страницы: `[+0]=R, [+1]=G, [+2]=B`, по 8 бит на компоненту. Это полноценный 24-битный RGB (8-8-8); BIOS API принимает значения `0..255` без дополнительного сдвига.

### Одна запись через BIOS

```asm
; Через BIOS PIC_SET_PAL — проще всего для разовых изменений
        ld      hl, 5               ; индекс цвета
        ld      e, 255              ; R (0..255)
        ld      d, 128              ; G (0..255)
        ld      a, 0                ; B (0..255)
        ld      c, #A4              ; PIC_SET_PAL
        rst     #08
```

### Прямая запись через WIN3

Пример пишет в **палитру буфера 0** (`#C3E0`). Для буфера 1 используйте `#C3E4..#C3E6`;
для одинаковых цветов на обоих буферах двойного буфера пишите в обе страницы.

```asm
; A = index, B = R8, C = G8, D = B8
SetPaletteEntry:
        in      a, (#E2)
        ld      (.saved_win3), a
        ld      a, #50
        out     (#E2), a            ; WIN3 = VRAM #50
        ld      a, e
        out     (#89), a            ; PORT_Y = индекс
        ld      a, b : ld (#C3E0), a    ; R (палитра буфера 0; буфер 1 -> #C3E4)
        ld      a, c : ld (#C3E1), a    ; G
        ld      a, d : ld (#C3E2), a    ; B
        ld      a, #C0
        out     (#89), a            ; PORT_Y в безопасную зону
.saved_win3 EQU $+1
        ld      a, #00
        out     (#E2), a            ; восстановить WIN3
        ret
```

Подробнее и про быструю запись всех 256 цветов одним проходом — см. [5.5 Палитра](05_palette.md).

## Пример: рисование простого шаблона

```asm
; Градиент: цвет каждой строки = номер строки (Y), горизонтальные полосы.
DrawGradient:
        ld      a, #50
        out     (#E2), a            ; WIN3 = #50
        xor     a                   ; PORT_Y = 0
.row:
        out     (#89), a            ; выбрать строку
        push    af
        ld      hl, #C000           ; буфер 0
        ld      (hl), a             ; цвет = номер строки
        ld      de, #C001
        ld      bc, 319
        ldir                        ; залить 320 байт строки
        pop     af
        inc     a
        jr      nz, .row            ; 0..255
        ld      a, #C0
        out     (#89), a
        ret
```

## Использование акселератора

Для эффективного рисования используйте аппаратный акселератор — см. раздел [5.6 Акселератор](06_accelerator.md).

```asm
        di

        ld      l, l                ; LD L,L — копировать строку
        ei
```

## Подводные камни

1. **8-битная арифметика X → заворот.** Смещение пикселя по X доходит до 319 и должно
   считаться 16-битно. Типичная ошибка — тайловый вывод, где `cell_x * 8` считают в `A`:
   ```asm
   ; НЕВЕРНО: для cell_x >= 32 заворачивается на 256:
           ld      a, cell_x
           add     a, a
           add     a, a
           add     a, a            ; wrap при cell_x >= 32

   ; ВЕРНО: 16-битно:
           ld      l, cell_x
           ld      h, #0
           add     hl, hl
           add     hl, hl
           add     hl, hl          ; HL = cell_x * 8, 0..319
   ```
   Симптом: правая часть картинки «сворачивается» в левую (граница ~середина строки).
2. **Второй буфер — это `#C140`, а не страница `#55`.** Переключение строк — через
   `PORT_Y`, а не прибавлением к адресу.
3. **Не подставляйте «X offset» дескриптора** (в знакоместах, напр. 40/48) как CPU-адрес
   пикселя (`#C040`/`#C180`) — получите сдвиг картинки.
4. **После доступа к VRAM/палитре** возвращайте `PORT_Y` на невидимую строку (`#C0`).
5. **Инициализируйте оба экрана** (`SetVMod B=1` и `B=0`) до прямого вывода.

## Ключевые моменты

> - 320×256, 1 байт = 1 пиксель, 256 цветов из палитры.
> - **CPU-view:** `WIN3 = #50`, `PORT_Y` (`#89`) выбирает строку, базы `#C000` (буфер 0) и
>   `#C140` (буфер 1). Физ. байт = `PORT_Y*1024 + (addr & #3FF)`.
> - Номер страницы `#5X` задаёт **режим записи** (норма/прозрачность/зеркало), а не регион
>   экрана; `#51`–`#59` для адресации пикселей не мапятся.
> - X — 16-битное смещение (0..319); 8-битная арифметика даёт заворот.
> - Включение: `Dss.SetVMod #81` для экранов 1 и 0.
> - Double buffering: бит 0 порта `#C9` (RGMOD); рисуем в скрытый буфер.
> - Палитра: `#C3E0` (буфер 0) / `#C3E4` (буфер 1), `PORT_Y` = индекс цвета (см. [5.5](05_palette.md)).
> - Для заливки/копирования — акселератор (см. [5.6](06_accelerator.md)).
